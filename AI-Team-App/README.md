# チームクエスト

大学生のためのグループワーク支援プロトタイプです。「スキル診断 → 自動役割分担 → 希望重複時のじゃんけん → 結果」を、**第1ステップ**の一連の体験として実装しています。その結果から**第2ステップ「活動・懸賞・振り返り」**へ進めます。表示は日本語です。

## 起動方法

**一番簡単な方法：`index.html` を Edge または Chrome で開きます。**

インストール、ビルド、APIキー、外部サーバー、インターネット接続は不要です。`index.html`、2つのCSS、4つのJavaScriptを同じフォルダーに置いてください。成果物の外部URLを開く場合だけ、そのURLへの通信が発生します。

VS Code では、次の方法でも起動できます。

- Live Server がある場合：`index.html` を右クリック → `Open with Live Server`。
- Node.js がある場合：このフォルダーのターミナルで `node preview.cjs` を実行し、`http://127.0.0.1:4173` を開きます。終了は `Ctrl+C`。`npm.cmd start` でも同じです。

Windows PowerShell の実行ポリシーで `npm` が拒否される場合は、`npm.cmd` または上記の `node` コマンドを使います。設定変更は不要です。

## 発表用の操作例（2～3分）

1. 右上の「サンプルで体験」を押します。架空の4人の回答を読み込みます。
2. スキルマップでメンバーの違いを説明し、「タスクを設定する」へ進みます。
3. 各タスクの担当人数・合計作業量・必要スキルを確認します。「AIで役割を分担する」を押します。
4. 田中さんと佐藤さんの「PPT・資料作成」の希望が重複しています。順番に画面を渡し、手を選びます。
5. 田中さんがグー、佐藤さんがチョキなら田中さんが勝利します。同じ手なら「あいこでしょ！」を体験できます。
6. 「担当を確定して進む」を押します。残りの作業を再配分し、結果カードと作業量の棒グラフを表示します。
7. 「結果を保存する」を押します。ブラウザの更新や「保存した結果」で復元を確認できます。

じゃんけんなしの発表では、PPT・資料作成の担当人数を2人にすると、そのまま結果へ進みます。3人以上のじゃんけんを試すにはスキル一覧から別メンバーの回答を編集し、「資料・デザイン」を希望に追加してください。

## 実装した機能

- 2～6人の順番入力、名前・8スキル・使える時間の必須チェック
- 希望／回避を各最大2つ選択。同じ項目の希望と回避の同時選択を防止
- メンバーの回答編集と全員のスキル一覧
- 7個の初期タスク。追加・編集・削除、1～6人の共同担当、複数の必要スキル
- 作業量はタスク全体の合計時間（0.5～100時間、0.5時間単位）。担当者で均等に分担
- スキル・希望・回避・時間・負担を考慮した自動マッチング
- 希望重複の検出、2～6人のじゃんけん、複数の担当枠、あいこ、勝者だけ／敗者だけの再戦
- 全員が選ぶまで手を非表示にする、同一端末の受け渡し画面
- じゃんけんの担当を固定した残りタスクの再配分
- メンバー別の担当・推薦理由・得意分野・作業量、グループの負担グラフ
- 入力・進行状況・じゃんけん途中の自動保存、結果の別保存と読み込み
- サンプルデータ、分析演出、じゃんけん演出、PC／スマートフォン対応
- キーボード操作、フォーカス表示、読み上げ用ラベル、動きを減らすOS設定への対応

## HP・EXP・懸賞・教員用評価の使い方

### 最短の体験方法

`index.html` を開き、上部の **「活動・評価」→「11操作デモをはじめる」** を押します。「次のデモ操作を実行」を順に押すと、指定の11操作を体験できます。既存のマッチングエンジンで実際に分担し、成果提出・確認・HP減点・懸賞・復活の記録を実際に作ります。

デモは架空の4人・12タスクです。ゲームオーバーのために同じ違反を繰り返すことはせず、別タスクの別違反を記録します。「1日進める」はこのデモだけの日時を動かし、端末の時計や通常の活動日時は変更しません。途中で自由に操作しても構いません。ガイドと作業内容が合わなくなった場合は「新しい11操作デモ」で再体験できます。

### 自分たちの診断結果で開始

1. 従来どおり診断・タスク設定・役割分担を完了します。
2. タスク設定で、合計作業時間とは別に、EXP用の**難易度・作業量・煩雑さ（各1～3）**を設定します。既存タスクの未設定値は各2です。
3. 結果画面の「役割を確定して活動開始」を押します。HP 100、EXP 0で開始し、当初担当と目標EXPを確定します。
4. 活動ボードでタスクを開き、「作業・成果物」で着手や成果物を記録します。
5. 「成果の確認」で確認者として累計貢献割合と理由を入力します。成果物と実際の貢献を確認したチェックを付けて承認します。
6. 「HP・懸賞・日程」で違反の確認、懸賞掲載、日付変更、正式な担当変更を行えます。
7. 「教員用評価」で比較・個別履歴・補救クエスト・免除・目標変更・コメントを確認します。
8. 「最終レポート」で本人の振り返りを入力し、終了理由を記録して活動を終了します。終了後の作業再開にも理由を残します。

### HPのルール

HPは0～100。通常のタスク完了で回復しません。次の違反は、管理者が事情と分配の妥当性を確認し、理由を記録して適用します。時間経過だけで自動的に減点はしません。

| 違反・達成 | HP | 条件 |
| --- | ---: | --- |
| 中間チェックで未着手 | −5 | チェック日を過ぎ、対象者の着手・確認済み貢献がない |
| 正当な理由のない期限超過 | −10 | 締め切りを過ぎ、未完了 |
| 期限超過後の応答なし | −5 | 期限超過の有効な記録があり、締め切り／最後の応答の遅い方から2日以上経過 |
| 協議のない放棄 | −20 | 管理者が事情を確認 |
| 補救・復活クエストの達成 | ＋10 | 成果を提出し、管理者が達成を確認。上限100 |

同じ活動の「タスク×メンバー×違反の種類」で重複を防止します。免除した違反も再度追加せず、元の記録を修正します。教員用の個別画面にある「HPの減点・回復履歴」から、理由を付けて減点を0にすると免除できます。変更前後・当初減点・理由は残ります。HPは訂正後の履歴を時系列に再計算し、各時点で0～100に収めます。

HP 0では「ゲームオーバー」と表示します。確認済みEXPや成果は消しません。補救クエストを確認するとHP 10で復帰できます。クエストIDの再承認と、同じメンバーの同一タイトル・同一成果の再提出を防ぎます。異なる補救作業は別のクエストとして扱います。

日付は日本時間で、中間チェック・締め切りは指定日の23:59までです。初期値は開始から3日後・7日後で、タスク詳細で理由付き変更が可能です。

### EXPと共同作業

基本EXPは **10 ×（難易度＋作業量＋煩雑さ）**。3・3・2なら80 EXPです。活動開始時に評価値を固定します。通常のタスク完了によるEXPを無条件に付与せず、成果物を提出してから確認者が累計貢献割合を承認します。

- 貢献割合は整数0～100%。全メンバーの合計は100%以下です。
- 共同作業は確認した割合に応じて基本EXPを分けます。25%なら80×25%＝20 EXPです。
- 前回から増えた割合だけを追加付与します。同じ承認や完了操作で二重計上しません。
- 100%に達したタスクを完了とします。部分成果も承認・記録できます。
- 追加貢献がない提出を確認する場合は、現在と同じ割合のまま理由付きで確認します。EXPを増やさず確認履歴を残します。
- 確認済み割合は減らしません。未確認成果物がある間は、懸賞掲載・正式な引き継ぎを停止し、元担当の貢献を先に確認します。
- 累積EXPにはアプリ上の上限を設けていません。基本EXPと懸賞ボーナスを分けて保存します。
- 成果物は説明とHTTP(S)の参照URLです。ファイル本体のアップロード・同期はありません。

### 懸賞（WANTED）のルール

懸賞掲載は、正当な理由なく放置された未完了作業を確認したうえで行います。公開中の懸賞を別のメンバーが引き受けると、現在の担当者を変更します。当初担当者、確認済みの貢献、目標EXPは変えません。

懸賞プールは基本EXPの20%です。**基本80、元担当が25%確認済み**の場合は次のようになります。

| 内容 | EXP |
| --- | ---: |
| 元担当に残る基本EXP | 20 |
| 引受担当の残り75%の基本EXP | 60 |
| 懸賞ボーナス | 16 |
| 引受担当が獲得可能な合計 | 76 |
| タスク全体の基本EXP＋ボーナス | 96 |

引受担当の残作業を部分確認する場合、ボーナスも引き受けた残作業の確認割合に応じて付与します。累計が20%のプールを超えないよう、小数第2位までで差分計算します。元担当の割合は掲載時の値から変えません。

引き受け前は、理由を記録して掲載を取り消せます。1タスクの懸賞は1回の引き継ぎに対応します。引き受け後の再懸賞化は実装していません。全員が共同担当のタスクは、別の引受メンバーがいないため掲載できません。

### 目標EXP・最終スコア

依頼の定義に合わせ、**各人の当初担当タスクの基本EXPの全額合計**を初期目標にします。共同担当でも各人にそのタスクの基本EXP全額を計上し、実績は実際の貢献割合で分配します。共同担当の担当範囲に合わせて目標を変更したい場合は、全員の正式な合意またはやむを得ない事情と理由を記録してください。当初目標は別に保持します。

```text
評価対象ボーナス = min(累積懸賞ボーナス, 目標EXP × 10%)
評価用の実績EXP = 確認済み基本EXP + 評価対象ボーナス
自動参考スコア = min(100, 四捨五入(評価用の実績EXP / 目標EXP × 100))
```

目標が0なら「評価対象外・要確認」です。教員の点数調整でこの扱いを上書きせず、まず目標と事情を確認します。通常の目標では教員がコメント・調整後の参考点を保存でき、変更・解除には理由が必要です。自動参考点、調整後参考点、累積EXPを分けて表示・保存します。正式な授業成績を決定する機能ではありません。

### レポートと保存

最終レポートは、HP 0でも確認済みの部分貢献や提出を表示します。「完了0件」を「無貢献」とは扱いません。例文は本人が状況を確認したときだけ任意に追加し、振り返りは自由に編集できます。

活動は `teamquest-activities-v1` に複数件を保存します。診断のやり直し、新しいデモ、再分担で既存の活動を上書きしません。「活動を切り替え」から戻れます。活動内では `hp`、`exp`（基本・懸賞・合計）、`evaluation`（評価用実績・自動点・調整後点）を独立した項目として保存し、HP履歴・EXP履歴・変更監査履歴も保持します。入力途中の成果物や確認フォーム、振り返りも保存します。

同じブラウザの**一つのタブ**での利用を想定しています。教員・管理者の認証、複数端末のリアルタイム共有、改ざん防止は実装していません。画面にも明示しています。

## 自動マッチングの考え方

これは外部AIを使わない、JavaScriptによる**デモ用の自動マッチング**です。画面にも明示しています。希望はスキル分野として入力し、必要スキルが一致するタスクを「希望するタスク」と判定します。複数スキルのタスクは、いずれか1つの希望との一致で希望者に含めます。

1. タスクごとに希望者数と担当枠を比較します。定員超過したタスクは、順番にじゃんけんで全枠を決めます。
2. じゃんけんで獲得した枠は固定します。複数のタスクを獲得することもあります。
3. 残りの担当は、得意度・希望一致の加点、避けたい分野の減点、作業量の偏りの減点から計算します。
4. 作業が大きい順に割り当て、担当移動・担当交換でスコアが改善する場合は調整します。
5. 各タスクの枠数を常に守り、同じタスクに同じ人を重複登録しません。再配分前にも未解決の希望重複を検出します。自動配分自体が新しい定員超過を作ることはありません。

負担は合計時間と、使える時間に対する作業量の両方を評価します。「誰か一人だけ未担当」もできるだけ避けます。ただしタスク数・共同担当枠が少ない場合や、じゃんけんで担当が固定された場合には、未担当者が生じることがあります。

使える時間の計算上の代表値は、**0.5／2／4／6時間**です。時間帯の回答から算出した目安であり、厳密な上限ではありません。目安を超える人は結果画面で明示します。全員が必ず希望どおりになる、必ず時間内に収まる、数学的に最適な組み合わせになる、という保証はありません。最終的にはチームで相談するための提案です。

### じゃんけんの複数枠ルール

- 全員同じ手、または3種類が出たときは、同じメンバーで再戦。
- 勝者が残り枠と同数なら、その勝者全員が担当を獲得。
- 勝者が残り枠より多ければ、勝者のみで再戦。
- 勝者が残り枠より少なければ、その勝者を確定し、敗者が残り枠を競う。

## 保存について

- `localStorage` の `teamquest-session-v1` に、入力と進行状態を自動保存します。
- 「結果を保存する」は `teamquest-results-v1` に、最新の結果1件を独立して保存します。再保存は上書きです。
- 「最初に戻る」で現在の入力をリセットしても、別保存した結果は残ります。
- 同じブラウザ・プロファイル・URLから開いてください。直接ファイルを開く場合とローカルサーバーで開く場合では、保存先が異なります。ファイルの移動でも保存データが引き継がれない場合があります。
- 保存がブラウザ設定や容量不足で拒否された場合は、その旨を表示します。プライベートブラウズやブラウザのサイトデータ削除では保存が失われる場合があります。
- 一つのタブでの利用を想定しています。複数端末の共有・アカウント認証は実装していません。
- じゃんけんの手は画面上で非表示にしますが、端末内の保存内容は暗号化していません。開発者ツール等からの閲覧を防ぐ仕組みではありません。

## 将来のAI API接続

`matching.js` の `MatchingService.propose({ members, tasks, locked })` を差し替え地点として分離しています。現在はローカル計算結果を `Promise` で返します。

将来はこのメソッドから自分のサーバーを呼び出し、サーバー側でAI APIを利用します。APIキーはサーバー側の環境変数で管理し、HTMLやJavaScriptには含めないでください。担当人数・担当者ID・固定された勝者・作業量の整合性は、AIの返答でも検証する必要があります。

## 検証

Node.js 20以降を使い、パッケージのインストールなしで実行できます。

```powershell
node --test tests/matching.test.cjs tests/app.test.cjs tests/quest.test.cjs
node --check app.js
node --check matching.js
node --check quest-engine.js
node --check quest-ui.js
```

ロジックテストは2～6人の全ての手の組み合わせと担当枠、100通りの生成タスクの時間合計・定員・固定担当を検証します。結合テストは軽量なDOM代替環境で入力制約・一連の画面生成・保存復元を確認します。実ブラウザの描画・クリック・スマートフォン表示の検証を代替するものではありません。
